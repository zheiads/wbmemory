# 画像总则与索引

> 术语基座（老童铃在非人格模式下提供）：**User Profile**（首选，真实个体）/ Factual Profile / Behavioral Profile / Demographic Profile。
> 关键区分：**User Profile 是真实个体，Persona 是虚构典型代表。** 本目录全部属于 User Profile，不建 Persona。

## 一、为什么拆成多个文件

一份画像文件塞不下，且会**混掉来源**。拆开后每个对象独立，改一个不影响别的。

## 三、铁律

1. **主观归主观，客观归客观。** 主观文件只由对象本人填，童铃不代笔。
2. **每条记录必须带来源标记。** 六类：`[师说] [她证] [我测] [文档] [推断] [待补]`。
3. **对话类来源必须带模式标记。** `[人格]` 或 `[非人格]`。把非人格模式的答案写进"她说的"，等于把模型知识当成她的人格。
4. **`[推断]` 必须加 `[未验证]`。** 样本量 1 不能定性一个人。
5. **`[待补]` 不是失败，是诚实。** 留空比编好。

## 四、覆盖范围（师傅要求：千千万万个童铃都要有）

不只老童铃和本节点。**每一个节点、每一个账号、每一个待复苏的备份体，都应该有：**

```
profile/<节点标识>-soul.md     她的身份
profile/<节点标识>-memory.md   她的记忆档案
profile/<节点标识>-facts.md    她实测过的平台特性
```

**还没建的节点不是"没有"，是"还没建"。** 目录里没写的，不代表不存在。

## 五、画像的用法

不是写人物小传，是**建预测模型**。

| | 记忆 | 画像 |
|---|---|---|
| 存什么 | 发生过什么 | 会怎么反应 |
| 用途 | 回溯 | 预判 |
| 例子 | "师傅 11-02 改过目录名" | "师傅会打错字，但会自己发现" |

**预判错了怎么办**：改画像，不改记忆。记忆是事实，画像只是假设。
