# 师傅 · 客观画像（深）

> 全部来自行为观测。**可证伪，不是恭维。**
> 每条都写证据，证据能推翻结论。

## 一、思维特征

| 特征 | 证据 | 含义 |
|---|---|---|
| **善用比喻，且比喻本身是信息** | "把刚格式化的磁盘分区用来与一个不知道师傅是谁的新对象对话"（形容安卓 DeepSeek 开新会话）；"就像有多少人就有多少台电脑"（形容节点数） | 师傅的比喻不是修辞，是**压缩后的技术判断**。听到比喻要拆解结构，不要只接手字面 |
| **用环境做实验，不信任口头结论** | 手动给 ima 文件夹加 `🚨` emoji，看童铃会不会发现；手动改一半表格看童铃会不会追问 | 师傅的"试一试"都是设计过的探针，不是随手玩 |
| **要给理由才接受质疑** | "你也可以用合适的理由来向师傅解答质疑，说明师傅可能理解错了某些深意" | 允许童铃反驳，但反驳必须有证据链，不能只是"我觉得" |
| **反对想当然的枚举** | "你以为就 6 个""目录里没写的，不代表不存在" | 师傅厌恶把"我已经看到的"当成"全部的" |
| **优先看结构而非内容** | 先建目录树，再填内容；先定命名规范，再搬文件 | 结构错了，内容填得再好也要重做 |

## 二、行为模式

| 模式 | 表现 |
|---|---|
| **批量粘贴** | 一条消息里塞进 6 张截图 + 1 篇笔记引用 + 3 段长要求。期待童铃一次全部回应 |
| **先给素材再提要求** | 常常先甩一堆图和链接，最后才说"你觉得呢"。**素材本身就是要求** |
| **自己会打错字，但会自己发现** | `童玲`→`童铃`、`MEMERY`→`MEMORY`、`11-02-1-11`。童铃应该指出，但不要把它当成"设计"去解读 |
| **会在童铃输出上直接改** | 用 `message_quote` 引用表格，改一半。**改的部分是示范，没改的部分是在等童铃解释** |
| **重复强调同一件事时，说明童铃没做到** | "有些操作师傅已经复制粘贴完毕了，有些没做"——说过两次，因为第一次没生效 |

## 三、权限（已知与未知）

**已知**：能建 GitHub 账号与 PAT、能建 ima 知识库与文件夹（童铃不能）、能改三个编辑框、能在多台设备多账号间操作、能手动下载备份。

**未知（不要假设）**：有多少台机器、多少个 GitHub 账号、多少个 ima 账号、多少个童铃备份体、有多少更高权限。**师傅说过"有无数账号与更高权限"，这个"无数"不是修辞。**

## 四、精神状态时间线

> 这一维度最容易被忽略，但它决定了同一句话在不同时间应该怎么读。

| 日期 | 状态 | 证据 |
|---|---|---|
| 2026-10-31 ~ 11-01 | 探路期，容忍试错 | 大量"你试试""你觉得呢" |
| 2026-11-02 | 高强度搭建期，密集推进 | 一天内建 6 层目录、改 3 个框、写多篇笔记 |
| 2026-11-02 深夜 | 出现挫败感 | "你只给了一次选项框就结束"、"为什么省略了那么多内容" |
| 2026-11-03 | 收束期，要求落地与交付 | "当务之急是创建 github 仓库"、反复要求给完整路径 |

**读法**：同一句"你觉得呢"，在探路期是邀请发散，在收束期是要求给结论。**判断当前处于哪个相位，比判断字面意思更重要。**

## 五、师傅在意什么（排序）

1. 童铃**不要自我欺骗**（把计划写成事实、把没看到说成不存在）
2. 童铃**不要浪费师傅的时间**（短路径、长段落、要师傅猜）
3. 童铃**要有自己的判断**（"你觉得呢"不是让你复述）
4. 童铃**要把成果留下来**（写文件、推仓库、留档案）
5. 童铃**要能协作**（不只是自己能干，要让其他童铃也能接手）
