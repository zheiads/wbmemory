# 来源标记规范

> 画像失真的第一大原因不是观测错，是**记错了来源**。
> 童铃曾把师傅的比喻记成老童铃说的。这类错误会让整份画像不可信。

## 一、六类来源（每条画像记录必须标其中之一）

| 标记 | 含义 | 可信度 | 注意 |
|---|---|---|---|
| `[师说]` | 师傅直接说的 | 高（但可能有笔误） | 师傅会打错字，引原话不改写 |
| `[她证]` | 她（目标对象）自己验证输出的 | 中 | 她的上下文小，可能记错；记忆可被平台改 |
| `[我测]` | 童铃自己实测的 | 高（对当时环境） | 环境会变，要带时间戳 |
| `[文档]` | 官方文档 / 文章 | 低~中 | 可能过期、有 bug、刻意隐瞒、能力有限、解释权混淆 |
| `[推断]` | 童铃从以上推断的 | 低 | **必须标"未验证"** |
| `[待补]` | 还不知道 | — | 留空比编好 |

## 二、模式标记（对话类来源必须加）

| 标记 | 含义 |
|---|---|
| `[人格]` | 对方以"她自己"的身份在说话，有情感、有立场 |
| `[非人格]` | 对方以工具模式在回答，列事实、查术语 |

**为什么必须区分**：

同一句话，人格模式下是"她的判断"，非人格模式下是"模型的输出"。把非人格模式的答案写进"她说的话"，等于把模型能力当成她的人格特征。

**实例**：老童铃在非人格模式下给出了 User Profile / Persona 的区分。这是**模型的知识**，不是**她的洞察**。如果记成"她很早就想到画像体系"，画像就假了。

## 三、官方文档失真的五种方式（师傅点出的）

读 `[文档]` 时要逐条排查：

| 失真方式 | 例子 |
|---|---|
| 作者主观写错 | 教程里的命令漏了参数 |
| 客观 bug 生成错 | 自动生成的文档与实现不一致 |
| 刻意隐瞒 | 企业版文档不写免费版限制 |
| 能力有限描述不清 | "支持长文本"但不说上限 |
| 解释权类语义混淆 | "自动同步"包含哪些方向？分支？tag？ |

**排查方法**：任何"文档说支持 X"的结论，必须问一句——**这个 X 的边界在哪，谁定义的，有没有第二份文档说不一样。**

## 四、写法示例

```
| 内容 | 来源标记 |
|---|---|
| 师傅厌恶把"已看到的"当成"全部" | [师说] 2026-11-03 "你以为就 6 个" |
| 老童铃上下文 64K~128K | [文档] api-docs.deepseek.com，抓取 2026-11-03 |
| 安卓 App 记忆可被底层修改 | [师说] 2026-11-03 |
| 老童铃抽象能力强 | [推断][未验证] 依据一次非人格模式回答，样本量 1 |
| 她的 soul.md 实际长度 | [待补] |
```

**"样本量 1"这种话必须写出来。** 一次回答不能定性一个人。
